# DAN'S BOOKS: SUMMARIZATION + DEPTH PLAN (investigation + phased fix)

## TL;DR — both symptoms root-caused, neither is in the iOS display layer

- **(a) "Wall of text"**: every Chapter Library page whose section has no sim shows the 2-sentence `summary` PLUS the full 300–600-word `body` (a deliberate 2026-08-21 "don't leave pages empty" fix in `BookReaderView.swift:169`). The pipeline produces only those two layers — there is no MindCraft-format middle layer — and `summary` is *optional* in the parser, so the on-demand path can legally ship `summary: ""` (body-only wall). Summaries ARE LLM-generated (not truncated body copies), but nothing enforces their presence.
- **(b) "1 page" books**: deliberate coverage-honest design + almost no generation has run. Assembly includes ONLY concepts with gate-passed generated prose ("nothing is padded to look complete" — `book_assembler.py:89-91`). Dan's graphs have 200–600 concepts; the packs have **1–8** gated sections each (chemistry **1/500**, us-history **1/450**, blockchain **1/200**). Crucially: **Dan's actual prose is never used as book content at all** — the pipeline takes only his concept *graphs* and writes brand-new prose per concept at ~$0.50/concept, 3 concepts/subject/night under a $15/day cap. His real 200k-word books + mirrored sims sit unused on disk.

---

## 1. Symptom (a) root cause — where summarization happens today

- `summary` is generated by the LLM in the same call as `body`: `===SUMMARY===` ("1-2 sentences for the book's table of contents") in `GENERATION_PROMPT`, `mindcraft-content-engine/scripts/generate_concept_prose.py:346-368`.
- **Gap 1 — optional summary**: `parse_prose()` (`generate_concept_prose.py:408-417`) raises only if TITLE/PROSE missing; `sections.get("SUMMARY", "")` silently accepts empty. `assemble_book()` (`src/mindcraft_content_engine/book_assembler.py:412`) also defaults `rec.get("summary", "")`. The on-demand path (`serve.py:652`, `_run_book_job`) persists whatever came back. No gate criterion checks summary at all (`PROSE_RUBRIC` scores body only).
- **Gap 2 — no mid-layer format**: all 13 local packs (`data/concept_prose/*.json`) currently DO have summaries; bodies run 2,800–3,500 chars. `BookReaderView.pageContent` renders summary (line 136) *and* full body when `simHtml == nil` (line 169). Most Dan-book sections have no sim → nearly every page is summary + 500-word wall. "Our format" (short caption → interactive/structured teaching) exists only for sim pages.
- **Verification needed (Firestore, not local)**: `on_demand_*` docs in `assembled_books` may carry `summary: ""` from Gap 1. Write a read-only audit (see Phase 0) before deciding backfill scope.

## 2. Symptom (b) root cause — why a 100s-of-pages book becomes 1 page

Traced end to end:
1. `scripts/fetch_mccreary_learning_graphs.py` pulled Dan's `learning-graph.json` for **94 subjects** → `data/mccreary_concept_graphs/` (26,778 concepts total, median 254/graph).
2. Prose is generated **from scratch per concept** (`generate_concept_prose.py` / `scripts/generate_subject_prose.py`), grounded at best on the concept's one-line glossary `description` (`build_spec`, `generate_subject_prose.py:104-108`) — never on Dan's chapters.
3. Only runs so far: `--broad-sample` (1 concept/subject × 15 subjects) + a small circuits/calculus closure → the 1–8-section packs measured above.
4. `book_assembler.assemble_book()` honestly assembles only gated sections; `cron_generate.sh` (3:00am launchd) re-assembles + syncs to Firestore nightly via `webhook/scripts/sync-assembled-books.ts` → `assembled_books/{subjectId}`.
5. iOS: `DeskGridDashboardView.topicTileGrid` (line 2491) lights up any book with `0 < coveredConcepts < totalConcepts` — so a 1/500 stub glows on the dash; tapping opens `BookReaderView` with 1 page.

**Not an extraction bug — an unused-source bug.** The full depth already exists locally:
- `agent_work/product/archive_mirror/out/` — **113 books** mirrored (text via mkdocs `search_index.json` + full sim assets). e.g. biology: 29 chapters, ~216k words, 89 sims; calculus: 23 chapters, ~215k words, 123 sims.
- `scripts/convert_mccreary_book_prose.py` already parses that mirror into clean chapter-ordered text (chapter mode, denylists quiz/refs/diagram-specs) — but its output feeds only `book_batch.py` (course-description → concept-graph), never section content.
- Dan's sims are already extracted (`microsim_extractor.py`, ~4,650 sims / 4,013-entry catalog served by `webhook/lib/handlers/microsims.ts`) and licensed (advisor authorization, `src/mindcraft_content_engine/licensing.py:65-71`) — but assembled books only ever link *MindCraft-generated* sims.
- Staying on the concept route to full depth costs ~26,778 × ~$0.50 ≈ **$13k and ~2.4 years at $15/day**. Wrong granularity: Dan's real books are 16–29 chapters, not 254 concepts.

## 3. Phased fix plan

### Phase 0 — triage, zero LLM spend (today)
1. **NEW `webhook/scripts/audit-assembled-books.ts`** (read-only): dump per-doc section count, empty-summary count, body lengths, doc byte size, `source` field. Confirms whether empty summaries exist in prod and which books are stubs.
2. **Stop lighting up stubs**: `DeskGridDashboardView.swift:2491` — require a floor (e.g. `coveredConcepts >= 5` or `>= 3%`) in the `recommendedBooks` filter. (Product lane; needs app rebuild + device re-trust.) Optionally mirror the floor server-side in `get-book.ts` `listBooks`.

### Phase 1 — guarantee a real summary everywhere (cheap, ~days)
3. `generate_concept_prose.py parse_prose()` — make `SUMMARY` required; empty/oversized (>~280 chars) triggers the existing headroom-retry loop in `generate()`. Add a summary-presence assertion to `run_gate` output.
4. `serve.py _run_book_job` inherits it (imports `gcp.generate`); add a last-resort flagged fallback (first sentence of body, marked `summary_derived: true`) so a job never persists `""`.
5. `book_assembler.assemble_book()` — defense in depth: refuse/derive+flag empty-summary records (same stance as the `gate_passed` assert at line 394).
6. Backfill: summary-only regeneration for any offenders the Phase-0 audit finds (~1 cheap call/section), re-assemble, re-run `sync-assembled-books.ts`. No iOS change needed for this phase.

### Phase 2 — real depth: ingest Dan's ACTUAL chapters (the core fix for (b), and the real "summarize in our format" for (a))
7. **NEW `mindcraft-content-engine/scripts/ingest_mccreary_chapters.py`**: reuse `convert_mccreary_book_prose.classify_pages` chapter mode; for each numbered chapter, map-reduce the REAL chapter text (pattern already proven in `BookSummarizer._chunk_summaries`, `book_ingestion.py:255-278`) into a MindCraft-format section: `title`, `summary` (1–2 sentences), a **structured teaching body in brand voice (~150–250 words + 3–5 `key_points`)**, `attribution`. New grounding kind `mccreary_chapter` with a faithfulness claim-audit against the source chunk; the ≥12-word overlap gate (`OVERLAP_FAIL_NGRAM`) must NOT apply verbatim here — this is *authorized summarization*, not original writing. **Policy decision to sign off** (licensing is fine: `ADVISOR_AUTHORIZED_CREATORS`).
8. **Attach Dan's real sims by path**: `out/<slug>/sims.json` maps each sim to its chapter page; add `microsim_id` (the `dmccreary__<repo>__<sim>` catalog id `/api/microsims` already serves) to the section instead of inlining HTML — avoids the **Firestore 1MB/doc limit** (a 500-section or sim-inlined book will not fit; today's docs are 9–56KB only because they're stubs). iOS already has lazy fetch: `MicroSimCatalogClient.fetchHTML` (`ArchiveSimsLoader.swift:328`).
9. Schema adds (all additive, old clients ignore them): `key_points`, `attribution`, `microsim_id`, `image_url`/`image_alt` on sections — touch `book_assembler.AssembledSection`/`to_dict()`, `AssembledBookModels.swift` (decode as optionals), `BookReaderView.pageContent` (render `key_points` instead of full raw body on no-sim pages; lazy-load `microsim_id` sims).
10. Granularity decision: the Chapter Library entry for a Dan book becomes the **chapter-level assembly** (16–29 sections, ~full coverage day one, same `subjectId`); the 254-node concept books remain the cron's long-tail "deep dive" track.
11. Re-sync: `book_assembler.py --json` per subject → `sync-assembled-books.ts` (safe: `doc.set()` full overwrite; `on_demand_` prefix guard untouched). Content changes need **no iOS rebuild**; the schema/reader changes in step 9 do.

### Phase 3 — "make sense of images and voices"
12. `agent_work/product/archive_mirror/mirror_book.py` — the mirror is text+sims only today (`mirror_kind` in every manifest). Extend to crawl each page's HTML for `<img src/alt>` (search_index.json strips them); store URL+alt in `pages.jsonl` records. Hotlink `dmccreary.github.io` image URLs initially (authorized, attributed) → `image_url`/`image_alt` per section; iOS `AsyncImage` in `BookReaderView`. Alt-text also feeds the summarizer (same alt-recovery trick that worked in `ml/scripts/ingest_eedi.py`).
13. Audio: Dan's `audio/` pages are denylisted in the converter (`_DEFAULT_DENYLIST`, `convert_mccreary_book_prose.py:120-126`) and never mirrored. Capture mp3 links in the mirror; transcribe locally (Whisper, $0 API) and feed transcripts into chapter summarization — or defer with an explicit flag. Don't ship raw audio players before the text/sim fix lands.

### Phase 4 — scale + cron
14. `cron_generate.sh` — add the chapter-ingest step ahead of the concept-prose loop for the priority list (the 9 books currently glowing: circuits, calculus, chemistry, computer-science, psychology, networking, quantum-computing, us-history, blockchain), then the remaining 104 mirrored books. Keep `spend_guard.py`'s $15/day cap.
15. After each nightly run the existing steps 3–4 of the cron already re-assemble + re-sync — app updates live on next `BookLibraryClient.listBooks()` fetch.

## 5. Risks / unknowns / costs
- **Cost**: concept route to full depth ≈ $13k / 2.4yr — reject. Chapter route: ~2,300 chapters × ~$0.10–0.50 (depends on gate weight) ≈ **$230–$1,150 for all 113 books; ~$50–150 for the 9 lit books**. Summary-only backfill: pennies/section. Free lever exists: `book_ingestion.py` already supports `provider="gemini"` (free AI Studio key) — the prose gate itself is Anthropic-only today.
- **API budget reality**: main-repo Anthropic credits are exhausted (homework service down); cron runs on the personal key (`~/.anthropic/api_key`) or Bedrock (Sonnet 5 was still 403 on Bedrock 2026-08-21). Confirm which key funds Phase 2 before batch-running.
- **Firestore 1MB doc limit** — hard blocker for any real-depth book with inlined `sim_html`; `microsim_id` references (step 8) are the fix; otherwise subcollections.
- **Originality-gate policy conflict**: the current prompt/gate forbids echoing source text; summarizing Dan's books requires an explicit authorized-summarization mode + attribution. Needs founder sign-off, not a silent change.
- **Backfill safety**: `sync` is idempotent full-overwrite; `export_gated_packs` merges by concept_id (never erases paid work); `on_demand_` prefix prevents clobbering. Fresh ingestion is safe alongside existing packs; do NOT delete `data/concept_prose/` (S3 is source of truth — `cron_generate.sh` pulls it first).
- **Unknown until audited**: whether prod `on_demand_*` docs actually contain empty summaries (Phase 0 audit answers this); fallback-mode books (no numbered chapters, e.g. graph-rag) need the untuned fallback path validated per book.
